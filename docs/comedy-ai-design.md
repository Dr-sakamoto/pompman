# お笑いAI構想および機能設計

## 1. 基本構想と目的

- **お笑いAIの共同育成**: プレーヤー（芸人等）が集まり「面白い／おもんない」を学習させ、最強のお笑いAIを構築する。
- **ネタ作りの強化**: 完成したAIに相談しながらネタを作成し、クオリティを飛躍的に向上させる。
- **ブルーオーシャンでの独占**: プロの世界においてチームでAIを活用する先行者利益を取り、圧倒的に独走する。
- **独自性と人間性の担保**: 「自分たちで育成した企業秘密の非公開AI」とすることで、人間性や独自性を担保しながら成果を独占する。

## 2. 参加メンバー（教育者）

- **想定参加者**: ポンプマン、ギュインさん、からすみずさん、ヤッホイ、牛女などのプレーヤー。
- **賛同者の見込み**: 森左近など、「面白ければAIでも笑う」「AIが好き」というスタンスのメンバーの参画を見込む。

## 3. ビジネスモデルとエコシステム

- **初心者向け課金**: 既に面白いプロには不要でも、「もっと面白くなりたい初心者」を対象にネタ講評・相談サービスとして課金制にする。
- **教育者への収益還元**: 得られた収益を教育者に還元（バック）し、継続的かつ熱心なAI教育のインセンティブを作る。
- **三方良し（ウィン・ウィン・ウィン）の関係**:
  - **初心者（おもんないやつ）**: プロ全員に直接指導を受ける機会や交通費・時間を考慮すると、AIに課金する方が高効率かつ少ない労力で講評・相談が得られる。
  - **教育者（おもしろいやつ）**: AIを育てる過程でお笑い理論を整理でき、AI相談機能が無料で使い放題となり、質の高いAIを作れば収益も入る。
  - **お笑い界**: AI活用の新方法論が確立され、「面白いとは何か」の理論的議論が深まる。
- **批判に対するスタンス**: 苦労や努力を尊ぶ「汗かき主義者」からの反論・嫌悪感は想定内。悪いプロダクトであれば自然淘汰されるため、まずは実行に移す。

## 4. 具体的な機能設計と技術アプローチ

### スワイプUIによる「間・ニュアンス」のRLHF学習

- 言語化が難しい「お笑いの間」や「ニュアンス（ピッチ・抑揚）」を、マッチングアプリ風の左右スワイプ操作（「良い／悪い」）で直感的に評価。
- 人間のフィードバックによる強化学習（RLHF）を用い、非言語的な感性データを報酬スコアとしてAIにフィードバックする。

### 音声生成ベースモデルとバリエーション展開

- StyleTTS2など、テキストから「間の秒数」や「ピッチ」を微詳細に制御できる音声生成AIをベースに使用。
- 同一セリフ・シチュエーションに対して「間が0.3秒／1.0秒」「語尾を上げる」「低音でボソッと言う」などの変化を付けた音声を自動で複数パターン生成する。

### シチュエーション設定とパーソナライズ

- 「漫才のツッコミ」「日常のスカしたボケ」「コントのタメ」などのタグ（コンテキスト）に分けて学習させ、学習効率を最大化する。
- これにより、ユーザーごとの「おもろい・心地よいと感じる時間感覚のプロファイル」を構築する。

### パラメータのエクスポートと組み込み

- 学習された「間」のパラメータを出力可能にし、専用の「お笑い間合い音声アシスタント」としての利用や、Next.js / Expo等で開発するアプリの音声バックエンドへ組み込む。
